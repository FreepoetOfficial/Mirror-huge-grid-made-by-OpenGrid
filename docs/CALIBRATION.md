# 现场标定

## 1. 标定顺序

按以下顺序处理，避免多个问题叠加：

1. 只确认 12 个地址都能扫描到。
2. 确认每个地址对应哪一个物理板位。
3. 确认每块板的旋转方向。
4. 再调剪影阈值、残影与亮度。
5. 最后调按键坐标和涟漪参数。

## 2. 地址与板位

`hardware.layout` 不是按地址数值排序，而是物理屏幕从上到下、从左到右的矩阵。当前标定：

```json
"layout": [
  ["0x27", "0x2B", "0x2F"],
  ["0x26", "0x2A", "0x2E"],
  ["0x25", "0x29", "0x2D"],
  ["0x24", "0x28", "0x2C"]
]
```

若以后换板，最可靠的方法是一次只连接一块，或让程序一次只给一个地址写测试图案，记录其物理位置。不要因地址位丝印看起来规律就跳过实测。

## 3. 单板方向

`board_rotations` 与 `layout` 同形状，角度以顺时针为正。当前全部为 270°，等价于把单板内容逆时针转 90°：

```json
"board_rotations": [
  [270, 270, 270],
  [270, 270, 270],
  [270, 270, 270],
  [270, 270, 270]
]
```

若网页图案正确而实体某块旋转错误，只改该项，不要交换地址。

## 4. 相机背景

启动或点击重新校准时，让镜头前保持空场至少 4 秒。摄像头应固定，背景和照明尽量稳定。改变相机角度、移动背景、大幅改变光源后重新校准。

## 5. 噪点与漏检

出现散点时依次尝试：

1. 稳定照明，避免自动曝光频繁变化。
2. 小幅提高 `threshold`，例如每次增加 3–5。
3. 提高 `min_area_ratio`，过滤太小的连通域。
4. 确认镜头画面中没有持续晃动的窗帘、屏幕或反光。

轮廓缺失时反向调整：降低 `threshold` 或 `min_area_ratio`。每次只改一个字段并记录结果。

## 6. 残影

- 离开后只是缓慢暗下：减小 `fall_ms`。
- 极暗像素长期不灭：提高 `output_cutoff`。
- 固定背景误差长时间保留：减小 `stationary_timeout_seconds` 或略增 `background_learning_rate`。
- 静止人物过早消失：增大 `stationary_timeout_seconds`，或减小背景学习率。

残影重建是视觉运动判断，不是人物识别；无法同时保证“永不吞掉完全静止的人”和“所有固定伪影立即消失”。现场应根据互动节奏选取平衡点。

## 7. 亮度层次

实体只有两三个明显层级时：

- 确认驱动发送的是 0–15，而不是二值 0/15；
- 保持 `max_level: 15`；
- 增大 `depth_gradient_pixels` 让过渡覆盖更多像素；
- `gamma < 1` 会抬高暗部，`gamma > 1` 会拉开亮部；
- 检查 5 V 压降，供电不足会让高亮级压缩；
- 网页 CSS 的视觉效果与真实 LED 光学扩散不同，应以实物为准微调。

## 8. 涟漪

按下四角和中心附近的按键，网页与实体波源应位于相同位置。位置错时先修板位/旋转，不要用波速掩盖坐标错误。

- 想更慢：降低 `speed_pixels_per_second`。
- 想环间距更大：提高 `wavelength_pixels`。
- 想更柔和：提高 `ring_width_pixels`、略增 `attack_seconds`。
- 想持续更久：提高 `duration_seconds` 或 `decay_seconds`。
- 想更明显地扰动剪影：提高 `image_modulation`，但过高会造成闪烁。
- 按键响应慢：提高 `boards_per_frame`，同时观察 FPS 和 I²C 稳定性。

## 9. 每轮修改后的验证

```bash
python -m json.tool ~/opengrid-shadow/config.json >/dev/null
sudo systemctl restart opengrid-shadow
journalctl -u opengrid-shadow -n 50 --no-pager
curl -s http://127.0.0.1:8080/api/state
```

同时比较网页和实体：网页正确而实体错误，优先查 I²C、布局、旋转、供电；两者都错误，优先查相机处理与配置。
